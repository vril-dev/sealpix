# 見本

sealpix の一式（ブラウザ用コンポーネント、画像検証サーバー、復号サーバー）を、Docker Compose で手元に立ち上げて試すための見本です。

> 見本のバックエンドは、ユーザーの認証や権限の確認を省いています。本番では使わないでください。

## 必要なもの

- Node.js 24.15 以上と npm 11
- Docker（Compose v2）

## 起動

リポジトリのルートで実行します。

```bash
npm ci
```

```bash
npm run build
```

```bash
node examples/setup.ts
```

```bash
docker compose -f examples/compose.yaml up --build
```

ブラウザで http://localhost:8080/ を開きます。ポート 8080 がほかで使われている場合は、`SEALPIX_PORT` で変えられます。

```bash
SEALPIX_PORT=18080 docker compose -f examples/compose.yaml up --build
```

## 試し方

1. アップロードの画面で書類の種類を選び、写真を選びます。テストには、架空の書類の画像を使ってください。
2. 運転免許証を選んだ場合は、書類の四隅に丸を合わせて補正し、塗りつぶした結果を確認してから確定します。
3. 「保存したデータを確認する」から確認の画面を開き、「復号して表示」を押します。

## 構成

| サービス  | 内容                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `backend` | 見本のバックエンドです。画面を配信し、受け取ったデータを画像検証サーバーで検査してから保存します。復号は復号サーバーに依頼します |
| `inspect` | 画像検証サーバーです                                                                                                             |
| `decrypt` | 復号サーバーです。ホストには公開しません                                                                                         |

`node examples/setup.ts` は、`examples/.local` に次のものを作ります。このディレクトリは Git の管理対象外です。

- 鍵ペア（秘密鍵は `decrypt`、公開鍵はブラウザに配るファイルと一緒に置きます）
- バックエンドが各サーバーに接続するためのトークンと、各サーバーの設定ファイル
- ブラウザに配るファイル（`sealpix.js`、公開鍵、ポリシー、テンプレート）
- 保存先のディレクトリ（`data`）

注意:

- 秘密鍵のファイルは、作成したユーザーだけが読める権限（600）で作られます。コンテナの中のユーザー（UID 1000）とホストのユーザーが違う場合は読めないので、権限を調整してください。
- 作り直すときは `examples/.local` を削除してから、もう一度 `node examples/setup.ts` を実行します。それまでの暗号化データは復号できなくなります。
